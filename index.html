Prism — API gateway for LLM providers

One OpenAI-compatible endpoint for every team: hashed API keys, per-team rate limits and budgets, usage metering, provider failover and SSE streaming. Built to stay correct across horizontally scaled replicas.

  • Zero over-admission under concurrent load: an atomic Redis Lua sliding-window limiter plus reserve-then-settle PostgreSQL budgets.
  • Resilient by default: timeouts, retries with exponential backoff and jitter, health probes and automatic provider failover.
  • Streaming on Java virtual threads, with data and control planes split so the hot path scales on its own.

Stateless gateway replicas scale horizontally; Redis + Postgres keep limits and budgets consistent across them.

  1. Split data & control planes.The hot path stays stateless and scales out; admin traffic can't slow down requests.
  2. Rate limits in a Redis Lua script.Check-and-record is one atomic step, so replicas can't race each other past the limit.
  3. Reserve-then-settle budgets.Cost is reserved before the call and settled after, so concurrent requests can't overspend the last dollar.
  4. Virtual threads for SSE.Thousands of concurrent streams with plain blocking code. No reactive rewrite needed.
  5. Backoff with jitter.Retries spread out instead of stampeding a provider that is recovering.

Sliding-window rate limiter

Limit: 5 requests / 10 s. Spam the button and watch requests get admitted or rejected with 429 as they slide out of the window.

−10s−5snow
0 / 5 in window
The real thing: atomic check-and-record in Redis Lua 
-- KEYS[1] = rl:{team}   ARGV = now, window, limit, id
redis.call('ZREMRANGEBYSCORE', KEYS[1], 0, ARGV[1] - ARGV[2])
if redis.call('ZCARD', KEYS[1]) < tonumber(ARGV[3]) then
  redis.call('ZADD', KEYS[1], ARGV[1], ARGV[4])
  redis.call('PEXPIRE', KEYS[1], ARGV[2])
  return 1  -- admitted
end
return 0    -- 429: one round trip, no race between replicas
